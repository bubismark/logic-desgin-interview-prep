Flip-flops and latches: every type, from gates up

Every memory element used in digital design builds on the same handful of ideas, stacked on top of each other: two gates wired back into each other to make the first bistable element, a trick to remove its one illegal input combination, a second copy of it to turn "follows the input continuously" into "samples the input at one precise instant," and a small amount of extra logic in front of that to get every other flip-flop type you'll ever be asked about. Build it in that order and nothing here needs to be memorized — it can all be re-derived.

Why we need memory at all

A plain logic gate (AND, OR, NOR, whatever) has no memory: the instant its inputs change, its output changes too, and the moment the inputs go away, so does any trace that they ever happened. That's fine for computing a function of "right now," but completely useless for anything that needs to remember — a counter, a state machine, a register holding last cycle's result. You need a circuit whose output can stay the same even after the inputs that caused it have changed or disappeared. That circuit is called bistable: it has exactly two stable resting states, and once it lands in one, it stays there until deliberately pushed into the other. Every flip-flop and latch on this page is a different way of building, taming, and improving on that one idea.

The SR latch — the first bistable element

Take two NOR gates. Feed the output of each one back into an input of the other. That's the entire circuit.

11invalidforces both Q and Q̄ to 0 — they're supposed to always be opposites, so this isn't a real state at all
The forbidden state, worked out in plain English: with S=1, both of the bottom gate's possible outputs don't matter — NOR(1, anything) is always 0, so Q̄=0. With R=1, the same logic forces Q=0. Now both outputs are 0 at once, which should be impossible (they're wired to always be opposites). The real danger shows up when S and R both return to 0 at the same instant: the circuit has to "decide" which gate wins the race back to a valid state, and that decision comes down to microscopic, unpredictable differences in gate delay — the result is indeterminate. This single illegal combination is the entire reason every flip-flop built from this point forward goes out of its way to make it structurally impossible to apply S=1 and R=1 simultaneously.

The gated D latch — removing the illegal state

The fix: never let a circuit generate S=1 and R=1 at the same time in the first place. Take one input, D, invert it to get D̄, and gate both of them with an enable signal EN before they ever reach the SR latch's inputs.

This is called a latch specifically because of that EN=1 behavior: while enabled, Q doesn't just eventually reach D — it continuously tracks it, instantly, for as long as EN stays high. It's "transparent." That word is going to matter a lot in a moment.

Master-slave — turning "transparent" into "an instant"

A latch updates throughout its entire enable window — that's a problem for building a clock-synchronous system, where you want something to update at one precise moment, not over some fuzzy stretch of time. The fix is almost cheeky: chain two D latches, and drive their enables with opposite phases of the clock.

The edge-triggered D flip-flop

That master-slave pair is a positive-edge-triggered D flip-flop — the one thing every piece of RTL on this entire site is built from (always_ff @(posedge clk)). Real standard-cell libraries implement it more efficiently at the transistor level than two literal latches, but functionally it's the exact circuit above.

SR flip-flop

Edge-triggered version of the SR latch — conceptually complete, but you'll essentially never use one directly in modern RTL. It's covered here only because "what's the difference between this and a D flip-flop" is a fair interview question.

SKQ (next), at the edge
00hold
101 (set)
010 (reset)
11invalid — same forbidden state as the SR latch, just now sampled at an edge instead of held open

It still carries the SR latch's one real flaw forward. D solved that flaw by construction; the next two types solve it a different way.

JK flip-flop

JK fixes the SR forbidden state by turning it into something useful: when both inputs are asserted, instead of an illegal state, the output toggles.

JKQ (next)
00hold
101 (set)
010 (reset)
11toggle — the exact case that was illegal for SR

The modern way to build one: you don't reinvent a new storage element — you take a plain D flip-flop and put a little combinational logic in front of it that folds J, K and the current Q together: D = (J && !Q) || (!K && Q).

The classic version, and its gotcha: before standard-cell D flip-flops were universal, discrete JK chips (the 7473/7476 family) built this directly as a master-slave pair of NAND gates, with the feedback for J/K coming from the slave's stable outputs rather than through a separate D-style combinational block. That design was notoriously sensitive to a problem called "1s catching" (or "ones-and-zeros catching"): because the master stage is level-sensitive for the full duration the clock is on that phase, any brief glitch on J or K during that whole window — not just at a clean edge — could get latched and corrupt the output. Modern edge-triggered designs (true pulse-triggered internal structures, or the D-flip-flop-plus-logic version above) don't have this failure mode, which is a large part of why JK flip-flops have essentially disappeared from modern ASIC design even though they're still taught everywhere.

T flip-flop

Toggle flip-flop: holds when T=0, toggles when T=1. Built the same way as JK above, just simpler — a single XOR gate instead of the J/K combinational block.

Reset styles: asynchronous vs. synchronous

Asynchronous reset

A dedicated reset port on the flip-flop itself forces Q to a known value immediately, with no dependence on the clock at all — it works even if the clock has stopped. The catch: the moment reset releases matters just as much as when it asserts. If it de-asserts asynchronously, close to a clock edge, different flip-flops across the chip can sample that release on different cycles — a classic, nasty bug. The standard fix is "assert async, release sync": a small synchronizer that lets reset slam on instantly but only lets it lift in lock-step with the clock.

Synchronous reset

Reset is just another input muxed in front of D, and only takes effect on a clock edge — immune to glitches on the reset line (ordinary setup/hold timing filters it, same as any other data signal), but it does nothing if the clock isn't toggling, and it costs one more gate (the mux) sitting in the data path on every single flop.

Setup/hold violations and metastability

A common misread of a setup/hold violation: "the flop just captures the old value or the new value, and you don't know which." The real risk is worse than that. If D changes too close to the clock edge, the internal cross-coupled latch at the heart of the flip-flop can be pushed to a voltage between a valid 0 and a valid 1 — not simply "wrong," but undefined, for an unbounded (though usually very short) amount of time before it randomly resolves to one rail or the other. If that resolution takes too long, the next stage downstream can sample it mid-resolution too, propagating the uncertainty forward. This is exactly why crossing between asynchronous clock domains always needs a proper synchronizer, not just "a flop or two for good luck" — see the CDC & synchronizers topic on this site for the full treatment.

Where latches are still used on purpose

"Never use a latch" is a lint-rule simplification, not a law of nature — latches are smaller and lower-power than flip-flops, and show up deliberately in real designs:

Integrated clock gating (ICG)

Before ANDing an enable signal with the clock to shut off a clock tree branch, the enable is first passed through a latch that's transparent only while the clock is low. This guarantees the gated clock can only ever turn off cleanly (no glitch, no runt pulse) — a latch used specifically as a glitch filter, not as a register.

Pulsed-latch datapaths

Some high-performance, power-sensitive designs replace a chain of full flip-flops with latches plus a shared, narrow clock pulse generator — fewer transistors per bit, at the cost of a much trickier timing analysis (the whole point of a latch is time-borrowing across phases, and that only stays safe if the pulse width and skew are tightly controlled chip-wide). A specialist technique, not a default.

Gotchas

"A setup/hold violation just gives you the wrong-but-defined value."
No — it risks metastability, an indeterminate resolution time at an invalid voltage, which can itself cascade into the next stage's setup window.

"JK and T flip-flops are more efficient primitives than D."
Backwards in a modern flow — they're built FROM a D flip-flop plus extra combinational logic, so they're strictly more hardware, not less. The "JK is more powerful" framing is a holdover from discrete-logic eras before standard-cell D-FFs were universal.

"Latches are simply forbidden in good RTL."
Unintended latch inference is the real anti-pattern (an incomplete if/case in a combinational block) — latches used deliberately and knowingly (ICGs, pulsed-latch datapaths) are a legitimate, well-understood technique.

"Asynchronous reset is simpler, so it's strictly better."
Only the assertion is simpler — the release has to be synchronized, or you risk different flops leaving reset on different cycles.

"The SR latch's forbidden state is just a theoretical curiosity."
It's the literal reason every other flip-flop in this page exists — D removes it by construction, JK/T turn it into a useful toggle; nothing here was designed without that one failure mode in mind.

Cheat sheet

  • Bistable = two stable states, holds one until deliberately pushed to the other — the whole point of every circuit on this page.
  • SR latch: 2 cross-coupled NOR gates. Forbidden: S=R=1. Fails specifically when both drop to 0 together — a race.
  • D latch: SR latch + gating logic that makes S and R from D/EN, so S=R=1 becomes structurally impossible. Transparent while EN=1.
  • Master-slave: two D latches, opposite-phase enables — the standard way to turn "transparent" into "edge-triggered."
  • D flip-flop: the universal default. Three timing numbers to know cold: t_setup, t_hold, t_clk-to-Q.
  • JK: D-FF + D=(J&&!Q)||(!K&&Q). J=K=1 toggles. Classic discrete version: watch for "1s catching."
  • T: D-FF + one XOR with fed-back Q. T=1 toggles — the mechanism behind every ripple counter/clock divider.
  • Async reset: instant, clock-independent, but the release needs its own synchronizer. Sync reset: glitch-immune, but needs a live clock and a mux in the data path.
  • Metastability: a setup/hold violation risks an indeterminate resolution time at an invalid voltage, not just a wrong value — this is why CDC needs real synchronizers.
  • Latches aren't "bad" — accidental ones are. Deliberate ones (ICG, pulsed-latch datapaths) are a real, standard technique.
